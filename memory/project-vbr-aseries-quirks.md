A "lesser AI" built the **A-series example projects** (Aug 2026) to stress-test Bust and logged ~20 quirks (bugs/missing/doc-gaps). I triaged them by **root cause** (several "quirks" are one bug seen from different angles) — see the conversation for the full list. Clusters:

- **Coercion cluster (Quirks 1, 2, 12, 19, 21) — BUILT 2026-08-07.** Root cause: `apply_fn_sig` (resolver.rs, shared by local + qualified calls) only did borrows, NO numeric coercion — so call args got *no* adaptation at all (the report's "works locally" was wrong; `CtoF(100)` failed locally too). Fixes: (1) `apply_fn_sig` now calls `maybe_cast(arg, t)` for a ByVal `Plain(numeric)` param → int-literal→`100.0`, `Long` var / `Val`→`as f64`/`as i64` at *every* call site (Q1/Q2/Q21); (2) `builtin_vtype`: `Left`/`Right`/`Mid` reclassified `VType::Str`→`vt(Type::Text)` — they `.collect::<String>()` an *owned* String (only `Trim` is a real `&str` slice), so the existing `infer(arg)!=Str` borrow now fires for them (Q19) AND a redundant `.to_string()` disappears from `Dim s = Mid(..)`; (3) `InStr` lowering `.find(x)`→`.find(x).map(|p| p as i64)` so a bound position is `Long` not `usize` (Q12). Guard: compiled example `examples/arg_coercion.vbr` + snapshot in HAPPY (rustc-compiled). 3 snapshots updated (2 = redundant-clone removal, 1 = transpile-only string_options InStr). **The maybe_cast-at-call-site is exactly what IR consolidation should keep centralised.**
- **Quirk 24 — `/` semantics — BUILT 2026-08-07 (VB6 float `/`).** Len's call: `/` is *floating-point* division (VB6), NO `\` reintroduced (he never used it — `Int(a/b)` is his idiom), narrowing **truncates** (`Dim n As Long = 7/2` → 3, Rust wins, not VB6's rounding). Impl: resolver.rs Binary arm — when `op==Div`, `promote_to_double(side)` on each non-`f64` numeric operand (an **`as f64` cast**, not a `2.0` literal — so literal/literal like `Int(7/2)` is concrete and can take `.floor()`; a bare `7.0/2.0` is an ambiguous `{float}` that can't). Ripple: `Ok(a/b)`/`Some(a/b)` in a `Result<Long>`/`Option<Long>` fn now yielded `Ok(f64)` → **added payload coercion**: new `Ctx.ret_inner` (numeric inner of Result/Option return, threaded through `resolve_body`'s new `ret_inner` param + `emit_fn`), and `Stmt::Return` coerces an `Ok(x)`/`Some(x)` payload to it. Fixed examples: `option.vbr` (even-test `n/2*2=n` → `n Mod 2 = 0`; `Some(n/2)` now coerces); `result.vbr`/`result_e.vbr`/`converter.vbr` compile unchanged (payload/plain-return coercion). Tests: `tests/division.rs` (3). Docs updated (language_reference §2 + vb6 guide). **KNOWN FOLLOW-UP: the C backend still integer-divides** (`vbr c` diverges from `vbr run` on `/`); Python is already true-division (consistent). Also latent: `Ok(a/b)` coercion only fires at a `Return` site, not a bare-tail `Ok(x)` or `Dim r As Result<Long> = Ok(a/b)` — extend if it bites.
- **Rust-keyword collisions (18, 32, field #29)** and **Bust reserved words as names (17, 23, 27)** — handled in slice 1.

**SLICE 1 (quick wins) BUILT 2026-08-07** — `tests/quirks_slice1.rs` (4 tests) + the harness digit test:
- **Q31** `escape()` (transpiler.rs) now escapes `\r` (was missing) — `vbCrLf` no longer emits a raw CR into `format!`.
- **Q14** owned-`String` `Match` scrutinee lowered through `.as_str()` (resolver.rs `Stmt::Match`), gated on `infer(..).is_owned_string()` (NOT `VType::Str`, which is `&str` — `.as_str()` on `&str` is the unstable `str_as_str`) AND a `"…"` literal pattern present.
- **Q18/Q32** `rust_name()` now escapes Rust keywords: `is_rust_keyword` + `escape_rust_keyword` → `r#move` etc. **CRUCIAL**: `self`/`crate`/`super`/`_` pass through UNTOUCHED (codegen generates `self` from `Me`, `crate::`/`super::` paths — escaping them broke the Godot runner). `snake` in resolver is aliased to `rust_name`, so escaping is consistent across resolver+transpiler (incl. `passed_by_ref`).
- **Q17/Q23/Q27** `expect_ident` (parser.rs) gives a targeted "`To` is a Bust keyword…" message via new `lexer::keyword_word(&Tok)`, instead of cryptic "expected a name, found To".
- **Q9** `.Length` on a Vec → `message_hint()` in main.rs `report_errors` (message-content hint, since `teaching_hint` is code-only) suggests `.Len()`/`.Count()`.
- **Q10** `test_fn_names` prefixes `t_` when a test description starts with a digit (Rust ident can't).
- **Q25** (bare `Return` in an event) is **surface-specific**, NOT a blanket fix: TUI events return `io::Result<()>` (want `Ok(())`), but GUI `update` returns `()`/`Task<Message>` and Web returns `bool` — a shared rewrite would break GUI/Web. Handled as a **doc note in tui_spec.md**; a proper per-surface lowering could be a later slice.

**SLICE 2 (three standalone bugs) BUILT 2026-08-07** — `tests/quirks_slice2.rs` (Q3, Q28) + manual (Q16):
- **Q3 Enum Display** — `emit_enum` now also emits `impl std::fmt::Display for <E> { write!(f, "{:?}", self) }` (delegates to the always-derived `Debug`), so `Debug.Print light`/`& light` print `Red` (unit) or `Circle(2.0)` (data). Added to 7 snapshots.
- **Q28 nested-`Vec` `For Each`** — `Index` render used `render_prec` (no paren guard); a deref'd receiver (a `For Each` binding over `Vec<Vec<_>>`) came out `*line[0]` = mis-parsed `*(line[0])`. Switched to `render_recv(inner)` → `(*line)[0]`.
- **Q16 local-shadows-module** — the `Module.method` arm treated `bitmap.Push(...)` as a call into module `bitmap` when a local var `bitmap` shadowed the sibling module. Guarded the qualified branch with `ctx.binding(m).is_none()` (VB scoping: a local shadows the module).

**SLICE 3 (Q11 builtins) BUILT 2026-08-07** — `Asc`/`IIf` both parse as ordinary calls (no parser change): `lower_builtin` gains `("asc",1)` → `s.chars().next().map_or(0, |c| c as i64)` (lenient, empty→0; `builtin_vtype "asc"`→`Long`) and `("iif",3)` → `(if cond {{ a }} else {{ b }})` (lazy Rust if-expr — VB evaluates both arms, we don't; **infer** iif from `args[1]`; **owns** a `&str` arm that must unify with a `String` sibling). Also fixed a latent **`Chr` bug**: `Chr(Asc(c)+1)` mis-grouped (`as` binds tighter than `+`) — arg now parenthesised (`(((..)) as u8) as char)`). Guard: compiled `examples/asc_iif.vbr` in HAPPY.

**SLICE 4 (Q15 multiline) BUILT 2026-08-07** — reframed from "multiline lists" to the **general Python rule**: inside an open bracket `(`/`[`/`{`, a newline is just whitespace (Bust is newline-terminated like Python/VB, not `;`-terminated). One lexer change: a `depth` counter (++ on `([{`, -- on `)]}`, `.max(0)`) and the `Newline` token is only emitted when `depth==0`. Safe because strings/`Text`/`Rust`/`Python` blocks are captured as whole tokens (`capture_inline_block`) so their brackets never reach the counter. Also added **trailing-comma tolerance** in the parser (list literal, struct literal, method-call args, function-call args — each: after eating a comma, break if the closer is next). **Deliberately NOT extended to `"…"`** — stays single-line/no-escape; `Text…End Text` owns multi-line strings (Len agreed: 3 orthogonal tools, no overlap). Guard: compiled `examples/multiline.vbr` (list+call+struct, all with trailing commas) in HAPPY. Docs: language_reference §2 "Wrapping across lines" + vb6 guide.
